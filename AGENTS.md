# Working on Arandu Activity Log

This is an Arandu package: the activity log of spatie/laravel-activitylog v5,
adapted to Arandu. One entity with an embedded Hesape Model, one logger that
records under the caller's Grant, one service that reads and cleans behind a
policy, and two read routes. It is a Go module somebody `go get`s and wires by
hand in their own `bootstrap/app.go`; there is no service provider, no container
and no discovery.

## The gates

Nothing is finished until all four exit zero.

```sh
export GOWORK=off
gofmt -l $(find . -name '*.go' -not -path '*/testdata/*' -not -name '*.kyse.go')
go build ./...
go vet ./...
go test -race ./...
```

`aru doctor` is not one of them: it reads applications, and this is a library.
`tests/Unit/audit_test.go` proves what the doctor would have: every exported
`ActivityService` method authorizes before it reaches the model, no tenant is
read from a request, and `arandu.mod.toml` says what the code does.

## The rules this package keeps

1. **An entry's tenant is the Grant's.** The logger records under the Grant the
   caller's own action was authorized with; the model stamps `data.Tenant(g)`.
   Nothing a caller names chooses whose log an entry lands in.
2. **Reading and cleaning go through the policy.** `ActivityPolicy` denies
   everything; an application opens the log with its own policy in
   `Config.Policy`.
3. **A record's change is written with the record.** `Logger.Save`,
   `Logger.Delete` and `Logger.Restore` run the record's write and its entry in
   one transaction.
4. **Spatie decides what is recorded; Arandu decides how.** A difference from
   Spatie v5 is written in the package documentation in `module.go`, with its
   reason.

`ActivityQuery.go` is generated by `aru model:build` and never edited.

Everything in the source is in English. Tests go under `tests/`, `tests/Unit`
declaring `package unit_test` and `tests/Feature` declaring `package
feature_test`.
